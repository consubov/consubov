Ambos têm identidade/cache namespaces diferentes para não converter automaticamente instalação lab em candidata. Recusar modo/outputs ambíguos. Não depender de flag runtime ou esconder DOM. Remover manualChunk auth-client do candidato. Sourcemap público desabilitado no candidato ou analisado integralmente pelo gate. Não reconstruir Fazendas.
2. **Candidato com falha segura.** Criar entry/runtime pequeno com identidade ADM, mensagem funcional de acesso indisponível enquanto autenticação administrativa real não estiver contratada; nenhum privilégio, credencial, MFA fictício, fixture, store ou UI de sucesso mock. Não importar `App.tsx`, `@consubov/ui` ou barrel completo contracts nesse caminho; se necessária tradução, usar módulo ADM dedicado com apenas strings dessa tela. Isso é candidato de empacotamento, não autenticação de produção entregue. Documentar pendência de auth real.
3. **Bancada preservada somente no modo explícito.** Se mantida a SPA anterior, colocá-la inteira atrás do entry lab com identificação inequívoca de simulação e sem alegar licenças/grants reais. Preferência: retirar emissão client-side e MFA fake também da bancada, usar login API existente e expor apenas auditoria baseada em audit:view. Não adaptar o role local super_admin por suposição. CRUDs sem contratos permanecem indisponíveis ou simulações claramente restritas ao build lab; nunca no candidato. Não atribuir offline administrativo. Estado de sessão em memória, sem restauração arbitrária; falha API/401/403 bloqueia acesso e limpa dados visíveis. Não exportar rotas/mutações privilegiadas do entry candidato.

Porta diferente é origem diferente para SW/CacheStorage/IDB/localStorage, não isolamento de cookies por porta; não usar cookie compartilhado. Novo worker recusa host/origem incorretos e nunca registra na origem Fazendas. Remover bloqueio de zoom para a11y.

Nenhum /api, bearer, response administrativa, Fazendas/module URL, página autenticada dinâmica ou cache genérico de GET. Cache commit só após pacote íntegro completo; install falho mantém worker/cache anterior. Sem skipWaiting/claim forçado que interrompa trabalho; worker activation consentida e verificada. Cleanup só dos caches ADM pertencentes ao próprio modo e após sucesso, preservando N-1. Offline mostra shell sem privilégios, não dados administrativos antigos. Fetch cross-origin passa pela rede, sem cache.
